# Test pages

Local fixture site for visually testing the extension popup against known
scenarios, instead of hunting for real websites with the right defects.

## Usage

```sh
bun run testpages   # → http://localhost:4242
```

Open a scenario page, then open the extension popup. Every page carries a blue
"Expected" panel describing exactly what the relevant popup tab should show,
so a visual pass is just: open page → open popup → compare.

The index at `/` is generated by scanning this directory; a page's `<title>`
is its one-line description. Adding a scenario = dropping an `.html` file into
a tab folder. No registration anywhere.

For a step-by-step checklist of the current branch's changes, see
[TESTING.md](./TESTING.md).

## Layout

```
test-pages/
  server.ts        tiny node:http static server (run with bun)
  headings/        one page per heading-analysis scenario (positive + negative)
  links/           link extraction and status-check scenarios
  images/          image extraction/audit scenarios (+ static/ fixtures)
  assets/          script/stylesheet scenarios (+ static/ js & css fixtures)
  theme/           fake Shopify storefront (sets window.Shopify + window.__st)
  robots/          robots.txt scenarios (+ fixtures/*.robots.txt)
```

## Conventions

- Page chrome (expected panel, nav) uses no `h1`–`h6` tags, so it never
  pollutes heading scenarios. Keep it that way.
- Pages are self-contained: inline `<style>` only, except in `assets/` where
  external files are the point. Remember the chrome's inline style block and
  the `← all test pages` nav link count in Assets/Links totals.
- Folders named `static/` or `fixtures/` hold supporting files and are not
  listed in the index (no `.html` inside them).

## robots.txt scenarios

`/robots.txt` is origin-wide, so one static file can't cover multiple cases.
The popup fetches it from the page context, which means the request's
`Referer` is the page you're on. The server uses that: while you're on
`/robots/<scenario>.html`, `/robots.txt` answers with
`robots/fixtures/<scenario>.robots.txt` — and two scenarios are synthesized:
`missing` → 404, `server-error` → 500. From any other page it serves the
`allow-all` fixture.
